PROJECT SUMMARY – INVERSER MULTI-CAMPAIGN MARKETING PLATFORM

GOAL
Build a reusable marketing platform for InverSer that supports multiple products (campaigns), each with its own landing page, while sharing the same backend, admin panel, mentors, tracking and CSV system.

CURRENT STATE (CONFIRMED WORKING)
- Single backend (Node/Express + Mongo)
- Single admin panel (React)
- Single mentor system
- Campaign-based system implemented (campaign_key)
- Actions, links and tracking are campaign-aware
- Public routing works: /:campaign/:slug
- Legacy compatibility: /:slug redirects to /cpn/:slug
- Two campaigns exist: cpn (Certificación NeuroCoaching) and suitex
- Tracking stores events per campaign
- Admin panel partially implemented
- Frontend exists and is cloned from Lovable (LandingCPN)

CRITICAL CLARIFICATION (NON-NEGOTIABLE)
Multi-campaign DOES NOT mean “same landing with different buttons”.
Multi-campaign means:
- Each campaign can and must have its own landing (UI + copy + structure)
- All landings are generated and maintained INSIDE the SAME Emergent project
- No duplicated backend, admin or project

FINAL ARCHITECTURE
- One backend
- One admin panel
- One mentor system
- One tracking system
- One CSV system
- Multiple landing templates per campaign

IMPLEMENTATION REQUIREMENT – TEMPLATE SYSTEM
1) campaigns collection must include:
   - template_key (string)

2) Frontend routing:
   - /:campaign/:slug
   - Load campaign → read template_key → render matching landing component

3) Landing templates (created inside Emergent):
   - LandingCPN:
     - Existing NeuroCoaching certification landing
     - Must NOT be modified
   - LandingSuitex:
     - New landing, different structure and copy
     - SaaS / product-style landing
     - Sections: Hero, Benefits, How it works, CTA (demo), For whom, Footer
     - Uses action_key=demo

4) Admin panel:
   - Campaign CRUD must allow setting template_key
   - Show warning if missing template_key
   - Fallback to cpn allowed only as safety with visible warning

5) Actions & links:
   - Remain per campaign
   - Landing renders only actions for its campaign

6) Tracking:
   - Remains unchanged
   - All events store campaign_key

DELIVERABLE TO CLOSE THIS PHASE

- /cpn/noel-rivera renders LandingCPN
- /suitex/noel-rivera renders LandingSuitex

FUTURE PHASES (PLANNED, NOT YET IMPLEMENTED)

  - Campaign CRUD UI
  - Actions per campaign UI
  - Mentor edit with campaign selector
  - CSV import/export per campaign
  - Analytics per campaign

  - Link change history
  - Mentor status per campaign
  - Simple attribution via session/cookie (no PII)

DEPLOYMENT STRATEGY
